# GCP 서비스계정 + 도메인 위임 세팅 안내 (v3, 관리자 1회 작업)

목적: 봇이 직원 각자의 구글 캘린더에 닿게 하려고, "직원을 대신(impersonate)해 캘린더를 다루는" 서비스계정을 만든다. 개인 GAS와 달리, 한 번 설정하면 도메인(jobcenter.or.kr) 안 누구의 캘린더든 대행할 수 있다.

[주의 1] 결과물인 JSON 키는 조직 전체 캘린더를 열 수 있는 강력한 비밀이다. 서버에만 0600 권한으로 보관.
[주의 2] 파일럿 대상 직원은 모두 같은 워크스페이스 도메인(@jobcenter.or.kr)이어야 impersonate가 된다.

======================================================

## Part A. GCP 콘솔 (console.cloud.google.com)

1. 프로젝트 만들기
   - 상단 프로젝트 선택 -> 새 프로젝트(예: secretary-bot) -> 만들기 -> 그 프로젝트 선택.

2. Calendar API 켜기
   - 검색창에 "Google Calendar API" -> 사용 설정(Enable).

3. 서비스계정 만들기
   - 좌측 메뉴: IAM 및 관리자 -> 서비스 계정 -> 서비스 계정 만들기
   - 이름: secretary-bot-calendar -> 만들기 -> (역할 부여는 건너뛰어도 됨) -> 완료.

4. JSON 키 발급
   - 만든 서비스계정 클릭 -> "키" 탭 -> 키 추가 -> 새 키 만들기 -> JSON -> 만들기
   - JSON 파일이 다운로드됨. (나중에 서버에 넣습니다. 안전 보관.)

5. 클라이언트 ID 확인
   - 서비스계정 상세의 "고유 ID(숫자, client ID)"를 복사해 둔다. (Part B에서 필요)
   - 도메인 전체 위임은 Part B의 관리자 콘솔에서 이 client ID로 승인합니다.

======================================================

## Part B. 워크스페이스 관리자 콘솔 (admin.google.com)

6. 보안 -> 액세스 및 데이터 제어 -> API 제어 -> 도메인 전체 위임 관리(Domain-wide Delegation) -> 새로 추가

7. 클라이언트 ID = Part A 5번의 숫자 client ID

8. OAuth 범위(scope)에 아래 한 줄 입력:
   https://www.googleapis.com/auth/calendar

9. 승인.

   => 이제 이 서비스계정이 도메인 내 사용자를 대신해 캘린더를 읽고 쓸 수 있습니다.

======================================================

## 세팅 후 저에게 넘겨줄 것
1. JSON 키 파일 - 서버에 안전하게 넣습니다(제가 경로/권한 처리). 슬랙/채팅에 붙이지 마세요. 파일로 전달.
2. 파일럿 2~3명의 이메일(@jobcenter.or.kr) - 캘린더 impersonate 대상.
3. 파일럿 각자의 클로드 토큰(claude setup-token 결과) - 두뇌용. (이것도 슬랙 금지, 안전 전달.)

## 확인(검증)
세팅이 되면 제가 서버에서 "서비스계정으로 한 직원 이메일을 impersonate해 캘린더 조회"를 한 번 돌려, 실제로 그 사람 캘린더가 열리는지 먼저 확인합니다(빈 조회 = 안전).
