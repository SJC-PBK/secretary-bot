# 기획서 — v3 (다중 사용자 파일럿)

작성일: 2026-08-14
상태: 착수(파일럿)
원본: v2 운영 중 + 사용자 다중화 요구

## 목표
하나의 중앙 봇을 여러 직원이 각자 개인 비서로 사용한다. 사장님이 업데이트하면 전원 자동 반영. 각 직원은 **자기 클로드 계정(seat)** 으로 답을 받고 **자기 구글 캘린더**를 관리하며, 데이터는 서로 격리·비공개. (DX/AX 체험 확산 목적. 우선 2~3명 파일럿.)

## 확정 설계 결정 (2026-08-14)
- 접근: **클로드 팀 계정 보유자만** (각자 토큰 등록 = 자연 게이팅)
- 두뇌: **per-user 클로드 토큰** (질문마다 그 사람 seat로 `claude -p`)
- 캘린더: **워크스페이스 서비스계정 + 도메인 위임** (사용자 이메일 impersonate → 각자 캘린더). 관리자 권한 가능.
- 진행: **소규모 파일럿(2~3명)** 부터. 보안은 단계마다 강화.

## 아키텍처 변경 (v2 → v3)
- **사용자 등록부**: 단일 `ALLOWED_SLACK_USER_ID` → 등록부 `{slackUserId, email, claudeTokenRef}`. `isAllowed`=등록 여부.
- **두뇌 per-user화**: `claude.run(prompt, userToken)` — 스폰 시 `CLAUDE_CODE_OAUTH_TOKEN`을 그 사용자 토큰으로. (공용 claudebot 토큰은 폴백/제거)
- **캘린더 교체**: `lib/calendar.js` GAS 호출 → **googleapis + 서비스계정 JWT(사용자 이메일 impersonate)**. GAS는 은퇴(또는 개인용 폴백). 새 의존성 `googleapis`(또는 google-auth-library).
- **격리**: 리마인더·기억·프로필은 이미 userId 격리. 캘린더는 impersonate 대상 이메일로 사용자별.

## 사전 준비 (관리자 — 상세 안내서: docs/gcp-service-account-setup.md 예정)
1. GCP 프로젝트 + Calendar API 활성화
2. 서비스계정 생성 + JSON 키 발급
3. 도메인 전체 위임(client ID) 활성화
4. 워크스페이스 관리자 콘솔에서 그 client ID에 캘린더 스코프 위임 승인
5. 파일럿 2~3명: 각자 `claude setup-token` → 토큰을 사장님께 안전 전달(슬랙 금지)

## 보안 설계 (단계적 강화)
- 토큰·키: 서버 `.env`/파일 0600, claudebot 소유, systemd 하드닝(기존). 파일럿 후 **at-rest 암호화** 추가.
- 토큰 온보딩: 파일럿은 **관리자 수동 등록**(슬랙으로 토큰 받지 않음). 자동 가입은 후순위.
- 최소 권한: 서비스계정은 캘린더 스코프만. 정기 점검(누구 토큰이 등록돼 있나).

## 파일럿 완료 기준 (검증)
2~3명이 각자: ①봇 질문→**자기 seat로** 답 / ②리마인더 / ③**자기 구글 캘린더** 생성·조회·삭제 / ④**서로 데이터 안 보임**(격리) / ⑤한 명 토큰 문제 시 그 사람만 영향(격리 실패 없음).

## 결재 포인트
여러 직원 클로드 토큰 + 서비스계정 키(조직 캘린더 접근) 보관 = 보안·개인정보 결재. 관리자 협조 필요. 파일럿으로 위험 관리.
